# Job Titles → ESCO Labels (en / es / pt / ar)

Matches the 73,681 scraped job titles in `data/job_titles_full.csv` against
ESCO's official occupation taxonomy and attaches ESCO's real preferred
labels in English, Spanish and Portuguese, plus an Arabic translation.

## Why not ESCO's official Arabic label

This environment's network policy blocks all `*.europa.eu` domains, so the
official ESCO API/download site (the only source for ESCO's own localized
Arabic strings) is unreachable. ESCO's Arabic coverage was also only added
in v1.2+; the only complete, legitimately-mirrored ESCO occupations dataset
found (a public GitHub repo, `eworx-org/labourR`) is the v1.1.1 snapshot,
which predates Arabic. So:

- **en / es / pt** in `esco_label_en` / `esco_label_es` / `esco_label_pt`
  are ESCO's own official `preferredLabel` values (real ESCO data).
- **ar** in `esco_label_ar` is a professional Modern Standard Arabic
  translation of the matched ESCO English label, generated by Claude — not
  ESCO's own localized string. Flag this distinction if this data is used
  downstream (e.g. in the CV builder / ATS matching pipeline).

## Pipeline

1. `data/esco_occupations_{en,es,pt}.csv` — official ESCO v1.1.1 occupation
   classification (2,942 occupations), sourced from the public GitHub
   mirror `eworx-org/labourR` (`data-raw/esco_bundle_occupations_1.0.8/`).
2. `scripts/match_esco.py` — matches each row's `norm` title against ESCO
   preferred/alt labels: exact match first, then a token-overlap fuzzy
   match gated on a shared head word. Bare generic titles ("Manager",
   "Teacher", "Technician"...) are only accepted on an exact
   `preferredLabel` hit — ESCO's alt-label lists include many overly
   generic synonyms that otherwise cause false matches.
   Produces `data/job_titles_esco_matched.csv` plus the distinct matched
   occupation list `data/esco_matched_distinct_en.csv`.
3. `data/chunks/` — the distinct matched-occupations list split into
   ~310-row batches; `data/chunks/out/*_ar.csv` are Claude-translated
   Arabic labels for each batch.
4. `scripts/merge_final.py` — merges the Arabic translations back in to
   produce `data/job_titles_esco_final.csv`, the final deliverable.

## Output columns (`job_titles_esco_final.csv`)

All original columns (`rank,title,norm,family,seniority,tier,score`) plus:

| column | meaning |
|---|---|
| `esco_match_type` | `exact_preferred` / `exact_altlabel` (+ `_reordered` variants) = high confidence; `fuzzy_medium_conf` (score ≥0.65) = usually right, spot-check; `fuzzy_low_conf` (0.45–0.65) = roughly coin-flip accuracy, treat as a suggestion needing human review; `no_match` / `no_match_generic` = no confident ESCO occupation |
| `esco_match_score` | 0–1 token-overlap confidence score |
| `esco_concept_uri` | ESCO occupation URI (stable ID) |
| `esco_label_en` / `esco_label_es` / `esco_label_pt` | ESCO's official preferred label |
| `esco_label_ar` | Claude-translated Arabic label (see caveat above) |
| `esco_matched_variant` | which ESCO label/altLabel text the fuzzy match matched on |

Recommended usage cutoff for production/auto-applied tagging: `exact_preferred`,
`exact_altlabel` (+ reordered variants) and `fuzzy_medium_conf`. Treat
`fuzzy_low_conf` as review-only suggestions and ignore `no_match*`.
